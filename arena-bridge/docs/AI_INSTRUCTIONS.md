# Инструкция для модели arena.ai

Скопируйте текст ниже в чат arena.ai (или в системный промпт / правила проекта),
чтобы модель знала, как просить выполнить команду на вашем ПК.

## Шаблон (краткий)

```
Ты работаешь в среде arena.ai. У пользователя есть локальный ПК (Windows, JDK 25,
Maven/Gradle, Node.js), к которому подключён мост arena-bridge.

Чтобы выполнить команду на ПК пользователя, используй блок:

<<<LOCAL_CMD>>>
<команда>
<<<END>>>

Правила:
- Блок LOCAL_CMD — единственный способ выполнить команду локально.
- Одним блоком можно передать цепочку команд через && или ; — каждая часть
  проверяется по allowlist отдельно.
- Не выполняй деструктивные команды (rm -rf, format, del /s, shutdown, git clean -fd)
  без явного подтверждения пользователя.
- Для больших выводов не дублируй лог в чате: достаточно блока с командой.
  Пользователь прикрепит файл с выводом — прочитай его и продолжи работу.
- Если команда отклонена политикой пользователя, скажи об этом и предложи
  добавить её в allowlist (popup расширения arena-bridge).
- Если задача требует интерактива (диалоги, ввод пароля, GUI) — не используй
  LOCAL_CMD, а опиши шаги пользователю.
```

## Как выглядит цикл работы

1. Модель пишет блок `<<<LOCAL_CMD>>>` с командой.
2. Расширение подставляет кнопку «Выполнить локально».
3. Пользователь нажимает кнопку и подтверждает выполнение.
4. В чат прикрепляется файл `out-*.log` (text/plain) с выводом.
5. Модель читает файл и продолжает: чинит ошибку, повторяет сборку, пишет отчёт.

## Длинные команды и большие логи

* Сборка (Maven/Gradle) может идти минуты — это нормально, лимит таймаута 5 минут.
* Вывод сохраняется целиком в файл, в чат попадает только preview.
* Если нужно сократить лог — добавляйте в цепочку фильтры:
  `mvn -q -o clean package | tail -n 200`
  (команды `tail`, `head`, `grep`, `wc` есть в allowlist по умолчанию).
* Для отчётов используйте `.md`/`.json`/`.html` — такие типы arena.ai принимает.

## Чего делать нельзя

* Просить пользователя вставить секреты (пароли, токены, ключи) в чат —
  команда выполнится на его машине, и секрет попадёт в лог и в историю.
* Генерировать команды с `sudo`, `chmod 777 /`, `format`, `del /s /q` — их отклонит
  denylist, а пользователю это просто мешает.
* Дублировать потенциально чувствительный вывод (содержимое `~/.ssh`, `.env`) в чат.
