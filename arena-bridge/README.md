# arena-bridge

Мост между чатом **arena.ai** и вашим локальным ПК: модель в чате предлагает команду
в специальном блоке — расширение показывает её вам, вы подтверждаете запуск, команда
выполняется на вашей машине, а файл с выводом прикрепляется обратно в чат.

Никаких облаков и внешних сервисов: локальный HTTP-сервер слушает только `127.0.0.1`,
расширение — обычное Chrome/Edge MV3-расширение.

```
┌───────────────────────┐         ┌───────────────────────────────┐
│  arena.ai (веб-чат)   │         │  Локальный ПК (Windows/macOS) │
│                       │  HTTP   │                               │
│  content script  ◄────┼────────►│  bridge server                │
│  (ищет <<<LOCAL_CMD>>>)│  127.0.0.1:7842 │  allowlist + токен  │
│  background SW        │         │  exec → файл вывода → .log    │
└───────────────────────┘         └───────────────────────────────┘
```

---

## 1. Требования

| Что | Версия |
|---|---|
| Node.js | ≥ 18 ( LTS 20/22 ) — https://nodejs.org |
| Chrome / Edge | ≥ 116 (Manifest V3) |
| ОС сервера | Windows 10/11, Linux, macOS |

Зависимостей нет вообще: сервер использует только встроенные модули Node.js,
расширение — чистый JS. `npm install` не нужен.

## 2. Установка

### 2.1. Склонировать и запустить сервер

```bash
git clone https://github.com/vlalikoffc/vlarena.git
cd vlarena/arena-bridge
node server/index.js
```

Сервер создаст `server/config.json` (с токеном) и напечатает:

```
  arena-bridge — локальный сервер выполнения команд
  ------------------------------------------------
  адрес        : http://127.0.0.1:7842
  токен       : 8f2c…e91a
  рабочая папка: C:\projects\minecraft-client
  корни       : C:\projects\minecraft-client
  история     : C:\Users\<user>\.arena-bridge\history.json
  конфиг      : C:\…\arena-bridge\server\config.json
```

Полезные ключи запуска:

```bash
node server/index.js --port 7843          # другой порт
node server/index.js --workdir C:\proj    # рабочая папка по умолчанию
node server/index.js --config D:\conf.json # свой файл конфига
node server/index.js --print-token        # напечатать токен и выйти
```

### 2.2. Установить расширение

1. Откройте `chrome://extensions` (или `edge://extensions`).
2. Включите **Режим разработчика** (Developer mode).
3. **Загрузить распакованное расширение** → выберите папку `arena-bridge/extension`.
4. Перезагрузите страницу `https://arena.ai` (иконка расширения появится в тулбаре).

### 2.3. Сопрячьте расширение с сервером

Кликните по иконке расширения → вставьте **токен** из консоли сервера (и адрес,
если он нестандартный) → **Сохранить**. Зелёная точка в popup = сервер отвечает.

## 3. Использование

### 3.1. Инструкция для модели

Нажмите в popup кнопку **«Скопировать инструкцию для ИИ»** и вставьте текст в чат
arena.ai (или в системный промпт модели). Полный шаблон — в
[`docs/AI_INSTRUCTIONS.md`](docs/AI_INSTRUCTIONS.md).

Модель отвечает блоком:

```
<<<LOCAL_CMD>>>
mvn -q -o clean package
<<<END>>>
```

Расширение находит блок в ответе и показывает под ним панель:

```
arena-bridge · выполнить на вашем ПК
┌────────────────────────────────────────────┐
│ mvn -q -o clean package                     │
└────────────────────────────────────────────┘
[ C:\projects\minecraft-client        ] [ Выполнить локально ]
```

### 3.2. Запуск и результат

1. **Выполнить локально** → кнопка меняется на «Подтвердить выполнение»
   (двухшаговое подтверждение; автозапуска нет никогда).
2. После подтверждения — панель показывает exit code, длительность, имя файла
   и первые ~40 строк вывода.
3. Дальше:
   * **Прикрепить к чату** — файл `.log` кладётся в поле вложений arena.ai
     (файл в чат отправляете вы сами);
   * **Скачать .log** — файл сохраняется на диск;
   * **Копировать путь** — полный путь к файлу (ручное прикрепление);
   * **Показать полный лог** — весь вывод целиком в панели.

### 3.3. Где лежат файлы

| Что | Путь |
|---|---|
| Файлы вывода | `~/.arena-bridge/out/out-<время>-<rand>.log` |
| История | `~/.arena-bridge/history.json` (последние 200 записей) |
| Конфиг | `arena-bridge/server/config.json` |

## 4. Настройка политики безопасности

Всё редактируется в popup расширения (allowlist / denylist / рабочая папка) или
в `server/config.json`:

```jsonc
{
  "port": 7842,
  "host": "127.0.0.1",          // менять не нужно: сервер рассчитан на loopback
  "token": "<сгенерирован автоматически>",
  "workdir": "C:\\projects\\minecraft-client",
  "allowedRoots": ["C:\\projects"],        // где разрешено работать
  "allowedCommands": ["mvn", "gradle", "git", "npm", "node", "java", "…"],
  "deniedPatterns": ["rm\\s+-rf\\s+/", "del\\s+/[sfq]", "format\\s+[a-z]:", "shutdown"],
  "allowedProgramPaths": ["C:\\Program Files\\Java\\jdk-25\\bin\\java.exe"],
  "allowShellMetacharacters": false,      // true — разрешить `>`, `$(…)`, backticks
  "allowAbsoluteProgramPaths": false,     // true — разрешить программы вне allowedRoots
  "maxOutputBytes": 24000000,             // < 25 МБ (лимит вложений arena.ai)
  "execTimeoutMs": 300000,                // 5 минут
  "allowedOrigins": ["https://arena.ai", "https://*.arena.ai"]
}
```

Как это работает:

* **allowlist** — программа каждого сегмента команды должна быть в списке.
  Команда разбивается по `&&`, `||`, `;`, `|`, `&`, переводу строки, и **каждый**
  сегмент проверяется отдельно: `mvn package && rm -rf /` не пройдёт целиком.
* **denylist** — регулярные выражения, которые запрещают команду целиком
  (проверяется до allowlist).
* **shell-метасимволы** — по умолчанию запрещены перенаправления (`>`), подстановки
  (`$(…)`, backticks, `${…}`) и ввод (`<`): они обходят allowlist. Разрешаются
  флагом `allowShellMetacharacters`.
* **cwd** — должен находиться внутри `allowedRoots` (по умолчанию — `workdir`).
* **путь к программе** — если команда ссылается на файл (`.\gradlew.bat`,
  `C:\...\java.exe`), путь должен быть внутри разрешённых корней или в
  `allowedProgramPaths`.

## 5. Безопасность

| Мера | Реализация |
|---|---|
| Сетевой доступ | сервер слушает только `127.0.0.1`; наружу ничего не торчит |
| Аутентификация | токен 32 байта в заголовке `X-Token`, сравнение constant-time |
| Сопряжение | токен генерируется при первом запуске, хранится в `config.json` (chmod 600) |
| Автозапуск | невозможен: требуется два клика в чате |
| Allowlist + denylist | см. раздел 4 |
| Логи | все попытки (включая отклонённые) пишутся в `history.json` |
| Секреты | токен лежит в `chrome.storage.local` расширения и в конфиге; в чат не попадает |

Дополнительные рекомендации:

* Держите `workdir` в отдельной папке проекта — `allowedRoots` ограничивает урон
  при prompt-injection.
* Не храните в `workdir` SSH-ключи и `.env` с секретами.
* `server/config.json` не коммитится (см. `.gitignore`).

## 6. Ограничения

* Расширение подключается к `https://arena.ai/*` (и поддоменам). Если разметка чата
  изменится — перестанут находиться блоки; см. [`extension/selectors.md`](extension/selectors.md).
* Лимит вложения arena.ai — 25 МБ на файл. Сервер режет вывод на
  `maxOutputBytes` (по умолчанию 24 МБ) и помечает результат как `truncated`.
* Сжатые архивы приложить нельзя (их нет в списке разрешённых типов) — отдавайте
  логи в `.log`/`.txt`, результаты тестов в `.json`, отчёты в `.html`/`.pdf`.
* Автоматической отправки сообщения в чат нет — это осознанное решение
  (иначе prompt-injection мог бы сам выполнить и «отправить» что угодно).

## 7. Разработка

```bash
npm install                    # только для тестов (jsdom); в рантайме зависимостей нет
npm test                       # 38 тестов: сервер (22) + расширение (16)
npm run smoke                  # проверка запущенного сервера (health/exec/file)
npm run icons                  # перегенерировать иконки расширения
npm run demo                   # перегенерировать extension/demo.html (превью панели)
node --check extension/content.js && node --check extension/background.js
```

Тесты расширения запускаются в настоящем DOM (jsdom) и проверяют, что content
script находит блок `<<<LOCAL_CMD>>>`, вставляет панель, требует двойного
подтверждения и кладёт файл вывода в `input[type=file]` чата. Без `npm install`
эти тесты пропускаются, серверные — работают всегда.

Структура:

```
arena-bridge/
├── server/            # локальный агент (Node.js, без зависимостей)
│   ├── index.js       # CLI-точка входа
│   ├── app.js         # HTTP-сервер и маршруты
│   ├── lib/           # config, policy, exec, output, history, util
│   └── test/          # node --test
├── extension/         # Chrome MV3
│   ├── manifest.json
│   ├── background.js  # service worker, HTTP-клиент, хранение токена
│   ├── content.js     # поиск блоков, панель, прикрепление файла
│   ├── popup.*        # статус, токен, allowlist, история
│   └── selectors.md   # заметки по DOM arena.ai
├── docs/              # протокол, инструкция для ИИ, разведка DOM
└── tools/             # генератор иконок, smoke-тест
```

## 9. Правовая заметка

Проект не обходит авторизацию и не скрывает присутствие пользователя: он лишь
выполняет команды, которые вы сами подтверждаете кликом. Перед использованием
убедитесь, что правила arena.ai (ToS) не запрещают подобную автоматизацию —
ответственность за соблюдение правил лежит на пользователе.
